# Program 4 – Integrate Git with Docker for Source-Controlled Application Builds

## Description

This program demonstrates how to manage a Node.js Express application with Git and publish its source code to GitHub, then build and run a Docker image from that source. After a source-code change is committed, the image can be rebuilt to verify the updated application.

The Dockerfile uses a **multi-stage build** with `node:20-alpine`. The build stage installs the npm dependencies, and the runtime stage copies the application into a fresh Node.js Alpine image.

## Prerequisites

Install the following tools:

- **Git:** https://git-scm.com/downloads
- **Node.js and npm:** https://nodejs.org/ (needed to run the app locally and generate `package-lock.json`)
- **Docker Desktop** or Docker Engine: https://docs.docker.com/get-docker/
- A **GitHub account**

Check that the tools are available:

```bash
git --version
node --version
npm --version
docker --version
```

## Project structure

Create the following files in the `Program_04` directory:

```text
Program_04/
├── .dockerignore
├── .gitignore
├── Dockerfile
├── index.js
├── package.json
└── package-lock.json
```

`package-lock.json` is generated by `npm install` if it is not already present.

## Step 1: Create the project directory

If you are creating the project from scratch:

```bash
mkdir Program_04
cd Program_04
```

If you are using the supplied project, open a terminal in the existing `Program_04` directory instead. Do not create a second nested `Program_04` directory.

## Step 2: Initialize the Node.js project

If `package.json` already exists, keep it and proceed to the next step. Otherwise, run:

```bash
npm init -y
```

## Step 3: Create the application

Create `index.js` with the following contents:

```javascript
const express = require("express");

const app = express();
const PORT = 3000;

app.get("/", (req, res) => {
  res.send("Hello from Git + Docker Integration!");
});

app.listen(PORT, () => {
  console.log(`Server running at http://localhost:${PORT}`);
});
```

The application listens on port `3000` by default and responds to requests to `/`.

## Step 4: Install Express

Run this command from the project directory:

```bash
npm install express
```

This installs Express and creates or updates `package-lock.json`. The lock file helps keep dependency installation consistent.

Optionally test the application locally:

```bash
npm start
```

Open http://localhost:3000. The expected response is:

```text
Hello from Git + Docker Integration!
```

Stop the local server with `Ctrl+C`.

## Step 5: Create the Dockerfile

Create a file named `Dockerfile` with the following contents. These instructions match the updated project Dockerfile:

```dockerfile
# Stage 1: Build dependencies
FROM node:20-alpine AS build
WORKDIR /app
COPY package*.json ./
RUN npm install
COPY src/ ./src/

# Stage 2: Runtime image
FROM node:20-alpine
WORKDIR /app
COPY --from=build /app /app
EXPOSE 3000
CMD ["node", "src/index.js"]
```

The build stage installs the dependencies and copies `index.js`. The runtime stage uses `node:20-alpine`, copies the prepared application from the build stage, exposes port `3000`, and starts the server with `node index.js`.

## Step 6: Build and run the Docker image

Make sure Docker is running, then execute these commands from the directory containing the Dockerfile:

```bash
docker build -t program-4 .
docker run -it --name program-4-container -p 3000:3000 program-4
```

Open http://localhost:3000 and confirm that the application displays:

```text
Hello from Git + Docker Integration!
```

Useful verification commands:

```bash
docker images
docker ps
docker logs program-4-container
```

To stop and remove the container when finished:

```bash
docker stop program-4-container
docker rm program-4-container
```

If a container with the same name already exists, remove it before running a new container with that name.

## Step 7: Create a GitHub repository

1. Sign in to https://github.com/.
2. Select **New repository**.
3. Enter a repository name, for example `program-4-git-docker`.
4. Create the repository. If you plan to push this existing local project, creating the remote repository without an initial README avoids an unrelated first-commit merge.

## Step 8: Create a GitHub Personal Access Token (PAT)

For HTTPS authentication, create a Personal Access Token in GitHub:

1. Open **Settings → Developer settings → Personal access tokens**.
2. Create a token with the minimum permissions needed to push to the repository. For a fine-grained token, grant access to the target repository and repository contents as required.
3. Copy and store the token securely; GitHub may not show it again.

When Git prompts for an HTTPS password, enter the PAT instead of your GitHub account password. **Never put the token in `index.js`, the Dockerfile, README, or any committed file.** Do not share it or paste it into a command that may be saved in shell history.

## Step 9: Initialize Git and commit the project

Run the following commands from `Program_04`:

```bash
git init
git add .
git commit -m "Initial commit: Git and Docker integration"
git branch -M main
```

If Git has not been configured on this computer, set your commit identity first:

```bash
git config --global user.name "Your Name"
git config --global user.email "you@example.com"
```

Check that `.gitignore` excludes generated dependencies such as `node_modules`. Do not commit credentials or tokens.

> **Existing repository note:** If this project directory is already inside a Git repository, do not run `git init` again. Run the add and commit commands from the existing repository root instead.

## Step 10: Link the local repository to GitHub

Replace `<username>` and `<repository>` with your GitHub username and repository name:

```bash
git remote add origin https://github.com/<username>/<repository>.git
git remote -v
```

If `origin` is already configured, inspect it with `git remote -v` rather than adding it a second time.

## Step 11: Push the source code to GitHub

```bash
git push -u origin main
```

Authenticate with your GitHub username and PAT if prompted. Refresh the GitHub repository page and verify that the project files are present.

## Step 12: Rebuild the image after a source-code change

Change the response text in `index.js`, for example, then commit and push the change:

```bash
git add index.js
git commit -m "Update application response"
git push
```

Rebuild the Docker image from the updated local source:

```bash
docker build -t program-4 .
docker rm -f program-4-container
docker run -d --name program-4-container -p 3000:3000 program-4
```

Refresh http://localhost:3000 and verify that the updated response is displayed. The Git commit records the source version, while the Docker build creates a new image from the checked-out files.

To inspect the built image and running application:

```bash
docker images
docker ps
docker logs program-4-container
```

## Expected outcomes

- The application source code is version-controlled in Git and pushed to GitHub.
- Docker builds an image from the project files using the updated multi-stage Dockerfile.
- The container serves the Express application on port `3000`.
- A later Git commit can be used to rebuild the image and verify the updated application response.
- The Git history and dependency lock file help track source changes and make builds more reproducible.

## Troubleshooting

- **Port 3000 is already in use:** Stop the process or container using that port, or map a different host port, for example `-p 3001:3000`, and open http://localhost:3001.
- **Container name is already in use:** Run `docker rm -f program-4-container` before creating the replacement container.
- **Git asks for a password:** Use a GitHub PAT for HTTPS authentication, not your GitHub account password.
- **`git push` is rejected:** Check that the remote URL is correct and that you have permission to push. If the remote repository already contains commits, reconcile the histories before pushing.
- **Dependencies fail to install:** Confirm that `package.json` is valid and that `package-lock.json` matches the dependencies; try `npm install` locally and rebuild.
